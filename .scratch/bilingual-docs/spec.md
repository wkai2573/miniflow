# 英文版文件與雙語展示站

## 問題陳述

miniflow 的 README、範例流程圖與展示頁目前全是繁體中文。不讀中文的開發者打開倉庫或 Hub 上的展示站，看到的範例標籤、導覽列與說明都讀不懂，也會誤以為函式庫只支援中文標籤。專案又沒有英文的入口文件，npm 與 GitHub 上顯示的第一印象是看不懂的語言。

## 解決方案

文件與展示站都提供英文與繁體中文兩個版本，英文優先。

- 倉庫根目錄的 README 改為英文，並新增繁體中文版 README，兩份頂端互放語言切換列。
- 展示站輸出兩個語言版本：英文放在輸出根目錄，繁體中文放在 `zh-TW/` 子目錄。每頁標頭有連到另一個語言同一頁的連結。
- 三份範例流程圖（電商訂單、CI/CD、RAG）在兩個語言下結構完全一致，只有文字不同。
- 英文頁面與繁中頁面各用各自語言的社群縮圖。

## 實作決策

**README 與套件**

- 英文 README 為主檔，繁體中文版另存為帶語言後綴的 README。兩份頂端互放語言切換列，繁中版內容沿用現有文字。
- 英文 README 的術語以專案詞彙表為準：節點 Node、連線 Edge、外框 Frame、格位 Grid Cell、節點類型 Node Kind、連線基調 Edge Tone。詞彙表沒涵蓋的詞（圖例、版面、標籤膠囊、主題變數等）由實作者翻譯，並在交付時列出清單供維護者確認。
- 英文 README 的規格範例改用英文標籤；繁中 README 的範例保持中文標籤，兼作中文標籤可正常運作的示範。
- README 中對範例目錄的說明，兩個語言版本各自用自己的語言描述。
- 套件的 description 改為英文。
- 兩份 README 靠人工同步。同步約定寫進專案的 AGENTS.md（該檔本身維持繁體中文）。不新增自動比對。

**範例規格**

- 三份範例規格各自改成接受語言參數的工廠，節點、格位、連線、外框、版面與節點類型只存在一份；所有使用者可見文字（流程標題、節點標籤與副標、連線標籤、外框標籤、圖例標題與各類型名稱、提示文字）從依語言區分的字典取得。
- 字典以語言為鍵並用型別約束完整性：兩個語言的字典必須有完全相同的鍵，缺任何一個就無法通過型別檢查。
- 英文範例沿用原本的語意，專有名詞採忠實翻譯。第三方服務名稱照原樣保留，台灣本地的金流名稱以通用英文寫法呈現。副標與技術棧名稱本來就是英文，維持不動。
- 支援的語言為英文與繁體中文，語言代碼分別是 `en` 與 `zh-Hant`；輸出目錄的語言後綴使用 `zh-TW`。

**展示站建置**

- 現有建置腳本的頁面外殼有大量寫死的繁中字串，包含導覽列、各頁標題與描述、提示氣泡、事件紀錄訊息、清空按鈕、頁面 `lang` 屬性與 meta 描述。全部改走同一套依語言區分的字典機制，與範例規格的字典方式一致。
- 展示站建置器成為一個新的純函式接縫：不接受外部輸入，回傳「相對路徑 → 檔案內容」的對照表，涵蓋兩個語言的所有輸出。建置腳本本體只負責呼叫它並把結果寫入磁碟，另外複製函式庫打包檔與縮圖。
- 輸出結構：英文頁面與 SVG 放輸出根目錄，繁中頁面與 SVG 放 `zh-TW/` 子目錄。兩個語言的頁面集合相同：總覽頁、三張獨立流程頁，以及 Web Component 互動頁。
- 英文佔用根目錄，既有頁面路徑保持有效，只是內容改為英文。這是刻意的取捨，在文件中不再做額外聲明。
- 每頁標頭放一個切換連結，指向另一個語言的同一頁。不做依瀏覽器語言的自動偵測與導向。
- 站內導覽連結與互動頁的切換按鈕都留在目前語言的目錄內。
- 每頁依語言設定 `<html lang>`、`<title>`、描述與社群預覽標籤。
- Web Component 互動頁在瀏覽器內執行的字串（事件紀錄、提示氣泡、清空紀錄、尚未觸發的提示）也依語言輸出，並且判斷「紀錄是否為空」不再依賴比對某句中文。
- 部署流程維持不變：整個輸出目錄原樣同步到 Hub，`zh-TW/` 隨之一併發佈。

**縮圖**

- 英文頁面的社群預覽圖沿用既有的縮圖檔名，內容換成英文標籤的 RAG 流程圖，寬度 800 的 webp，構圖與現有縮圖一致。
- 現有繁中縮圖改名為帶語言後綴的檔名，供繁中頁面使用。
- 英文縮圖在英文展示頁完成後，用本機瀏覽器對英文 RAG 流程圖截圖，再縮放轉成 webp。這是一次性作業，不進建置腳本。截圖與轉檔的步驟簡述記錄在開發說明中，以便範例改版時重做。

## 測試決策

**好測試的標準**：只驗證展示站建置器對外可觀察的輸出，不驗證字典的內部結構、模板字串的拼接方式，也不比對整份 HTML 的快照。

**唯一新增的接縫**是展示站建置器。函式庫本身（`render`、版面、路由、元件）這次不動，既有測試維持原樣，不為此加案例。

**要驗證的行為**：

- 輸出對照表同時包含根目錄的英文頁面集合，與 `zh-TW/` 底下的繁中頁面集合，且兩邊的檔案清單對稱。
- 各語言頁面的 `lang` 屬性正確。
- 每個頁面都含有連到另一個語言同一頁的連結，且站內導覽連結不跨語言。
- 社群預覽圖：英文頁指向主縮圖，繁中頁指向帶語言後綴的縮圖。
- 同一張範例圖在兩個語言下的節點 id、格位與連線集合完全一致。
- 兩個語言的每一份規格都能通過 `render` 的輸入驗證而不拋錯。
- 英文頁面不含寫死的繁中介面字串；繁中頁面保留原本的繁中內容。

**先例**：既有測試都是針對純函式的輸入輸出斷言，以字串包含與結構比對為主。新測試沿用同樣風格。

## 不在範圍內

- 詞彙表、ADR、`docs/agents/` 與 AGENTS.md 本身的英文化。
- 依瀏覽器語言自動偵測並導向。
- README 之間的自動同步檢查。
- 縮圖的自動化產生流程。
- 英文與繁中以外的其他語言。
- 函式庫本身的任何行為變更，包含圖例預設標籤等。
- 在 README 中新增指向線上展示站的連結。
- 調整 Hub 部署流程。

## 補充說明

- 英文優先是整個功能的原則：根網址、套件簡介、主 README 與預設縮圖全部以英文為準。
- 提交訊息依專案慣例使用繁體中文。
- 實作時請先切到功能分支，不要直接在 main 上作業。
- 建議的實作順序：先做範例規格字典化與展示站建置器接縫（含測試），再做 README 雙語與 AGENTS.md 約定，最後在英文頁面能正常產出後才做英文縮圖。
