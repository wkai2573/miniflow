Status: ready-for-agent

# 多語文件與展示站

## 問題陳述

miniflow 的使用者分布在讀英文、繁體中文與簡體中文的開發者之間。文件與展示站若只有單一語言，其他語言的讀者打開倉庫或 Hub 上的展示站，看到的範例標籤、導覽列與說明都讀不懂，也會誤以為函式庫只支援該語言的標籤。專案又需要一個通用的英文入口，npm 與 GitHub 上顯示的第一印象才不會是看不懂的語言。

## 解決方案

文件與展示站都提供英文、繁體中文、簡體中文三個對等的語言版本，英文為預設。

- 倉庫根目錄的 README 為英文主檔，另有繁體中文版與簡體中文版，三份頂端互放語言列。
- 展示站輸出三個語言目錄 `en/`、`zh-TW/`、`zh-CN/`。訪客打開根網址時，根頁面依瀏覽器的偏好語言導向對應的語言目錄，沒有對應語言就導向英文。直接打開任一語言目錄下的網址一律尊重網址，不再導向。頁面沒有語言切換連結。
- 三份範例流程圖（電商訂單、CI/CD、RAG）在三個語言下結構完全一致，只有文字不同。
- 所有語言的頁面共用同一張英文標籤的社群縮圖。

## 實作決策

**README 與套件**

- 英文 README 為主檔，繁體中文版與簡體中文版另存為帶語言後綴的 README。三份頂端互放語言列。
- 英文 README 的術語以專案詞彙表為準：節點 Node、連線 Edge、外框 Frame、格位 Grid Cell、節點類型 Node Kind、連線基調 Edge Tone。詞彙表沒涵蓋的詞由實作者翻譯，並在交付時列出清單供維護者確認。
- 簡體中文版的術語採詞彙表的簡體對照，用詞採中國大陸慣用詞。詞彙表每個術語都列一行簡體對照，即使與繁體字形相同；詞彙表本身仍是繁體中文。
- 三份 README 的規格範例各用自己語言的標籤：英文版用英文標籤，繁體版用繁體標籤，簡體版用簡體標籤。這也兼作各語言標籤都能正常運作的示範。
- README 中對範例目錄的說明，三個語言版本各自用自己的語言描述。
- 套件的 description 為英文。
- 三份 README 靠人工同步。同步約定寫進專案的 AGENTS.md，該檔本身維持繁體中文。不新增自動比對。

**範例規格**

- 三份範例規格各自是接受語言參數的工廠，節點、格位、連線、外框、版面與節點類型只存在一份；所有使用者可見文字從依語言區分的字典取得，包含流程標題、節點標籤與副標、連線標籤、外框標籤、圖例標題與各類型名稱、提示文字。
- 字典以語言為鍵並用型別約束完整性：各語言的字典必須有完全相同的鍵，缺任何一個就無法通過型別檢查。簡體字典手寫完整內容，與其他語言並列維護，不從繁體自動轉換。
- 支援的語言為英文、繁體中文、簡體中文，內部語言代碼分別是 `en`、`zh-Hant`、`zh-Hans`；輸出目錄名稱分別是 `en/`、`zh-TW/`、`zh-CN/`。語言代碼與目錄名稱各自獨立設定。
- 支援語言的清單只有一個來源，其他需要列舉語言的地方一律從它推導，包含展示站建置器的迴圈與測試。
- 英文範例專有名詞採忠實翻譯。第三方服務名稱照原樣保留，台灣本地的金流名稱以通用英文寫法呈現。副標與技術棧名稱本來就是英文，維持不動。

**展示站建置**

- 頁面外殼的所有文字，包含導覽列、各頁標題與描述、提示氣泡、事件紀錄訊息、清空按鈕、頁面 `lang` 屬性與 meta 描述，一律走同一套依語言區分的字典機制，與範例規格的字典方式一致。
- 展示站建置器是一個純函式接縫：不接受外部輸入，回傳「相對路徑到檔案內容」的對照表，涵蓋所有語言的輸出。建置腳本本體只負責呼叫它並把結果寫入磁碟，另外複製函式庫打包檔與縮圖。
- 輸出結構：根目錄只有導向頁；三個語言目錄各自放完整且對稱的頁面集合，包含總覽頁、三張獨立流程頁、三份 SVG，以及 Web Component 互動頁。
- 站內導覽連結與互動頁的範例切換按鈕都留在目前語言的目錄內，頁面之間沒有任何跨語言連結，也沒有語言切換連結。
- 每個內容頁的 `<head>` 放三個語言版本同一頁的 `hreflang` 替代連結。
- 每頁依語言設定 `<html lang>`、`<title>`、描述與社群預覽標籤。簡體中文頁面的 `lang` 為 `zh-Hans`。
- Web Component 互動頁在瀏覽器內執行的字串也依語言輸出，並且判斷「紀錄是否為空」不依賴比對某句特定語言的文字。

**導向頁與語言偵測**

- 根目錄的 `index.html` 是導向頁，頁面本身就是極簡的語言選單：列出 English、繁體中文、简体中文三個連結，每個連結的名稱用該語言自己的文字。`<head>` 放各語言版本的 `hreflang` 替代連結，預設版本標為 `x-default` 並指向英文。導向頁的 `lang` 為 `en`，社群預覽使用共用縮圖。
- 偵測在瀏覽器端執行，不依賴伺服器重導，也不依賴 Hub 的任何設定。偵測成功後用取代目前紀錄的方式導向，使用者按上一頁不會停在導向頁。
- 偵測規則依瀏覽器偏好語言清單的順序，取第一個有對應的語言：
  - `zh-TW`、`zh-HK`、`zh-MO`，以及帶 `Hant` 字形標示的代碼，導向繁體中文。
  - `zh-CN`、`zh-SG`，帶 `Hans` 字形標示的代碼，以及單純的 `zh`，導向簡體中文。
  - 字形標示優先於地區。
  - `en` 與 `en-*` 導向英文。
  - 其他語言視為沒有對應，略過並看下一項。清單為空或全部沒有對應時，導向英文。
  - 比對時不區分大小寫。
- 導向目標由目前的網址路徑計算：以導向頁所在目錄為基準，少了結尾斜線時自行補上，再接上語言目錄。不寫死任何部署前綴。
- 偵測邏輯寫成純函式，原始碼在建置時內嵌進導向頁，使導向頁沒有執行期依賴。
- 只有根路徑做偵測。直接進入任一語言目錄下的網址一律尊重網址，不導向、不儲存任何偏好、不記憶選擇。

**縮圖**

- 所有語言的頁面與導向頁共用同一張英文標籤的縮圖，寬度 800 的 webp，位於輸出根目錄。各語言目錄下的頁面以相對路徑指向它，導向頁直接指向同一張。
- 縮圖用本機瀏覽器對英文 RAG 流程圖截圖，再縮放轉成 webp。這是一次性作業，不進建置腳本。截圖與轉檔的步驟簡述記錄在開發說明中，以便範例改版時重做。

**部署**

- 部署流程不變：整個輸出目錄原樣同步到 Hub，且同步前會先清空 Hub 上該應用的目錄，所以輸出目錄只含現行結構，不留相容用的導向頁。

## 測試決策

**好測試的標準**：只驗證對外可觀察的輸出，不驗證字典的內部結構、模板字串的拼接方式，也不比對整份 HTML 的快照。

**測試接縫**：展示站建置器與三份範例規格工廠。函式庫本身的 `render`、版面、路由、元件不動，既有測試維持原樣。語言偵測不另設接縫：測試從展示站建置器的輸出取出導向頁，在假的偏好語言清單與假的網址位置下執行其內嵌腳本，驗證實際會部署的程式碼。

**要驗證的行為**：

- 輸出對照表的根目錄只有導向頁；三個語言目錄各自含完整的頁面集合，且檔案清單兩兩對稱。
- 各語言頁面的 `lang` 屬性正確。
- 導向頁含三個語言的連結與 `hreflang` 替代連結，預設版本指向英文。
- 每個內容頁含三個語言同一頁的替代連結，且畫面上的站內連結都不跨語言。
- 所有頁面的社群預覽圖都指向共用縮圖，相對路徑隨目錄深度正確。
- 導向行為：各地區與字形代碼的對照、偏好順序與略過不支援語言、單純中文導向簡體、字形標示優先於地區、大小寫不敏感、清單為空導向英文、網址缺結尾斜線時仍導向正確位置、導向時取代目前紀錄。
- 每個語言的每份範例規格都能通過 `render` 的輸入驗證而不拋錯；各語言的節點 id、格位與連線集合完全一致。
- 英文頁面與英文 SVG 不含中文字元。簡體頁面保留簡體內容，並與繁體頁面的對應文字不同。
- 測試本身從單一來源推導語言清單，沒有手動維護的語言陣列。

**先例**：既有測試都是針對純函式輸入輸出的斷言，以字串包含與結構比對為主。新測試沿用同樣風格。

## 不在範圍內

- 依瀏覽器語言導向以外的語言偵測，例如依地理位置或 Cookie。
- 記住使用者的語言選擇，包含 localStorage。
- 為舊的根目錄英文網址保留相容的導向頁。
- 修改 Hub 倉庫的設定，或依賴伺服器端重導。
- 為任一語言產生獨立縮圖，以及縮圖的自動化產生流程。
- 詞彙表、ADR、`docs/agents/` 與 AGENTS.md 本身的英文化或簡體化，詞彙表只加簡體對照行。
- 英文、繁體中文、簡體中文以外的其他語言。
- 函式庫本身的任何行為變更，包含圖例預設標籤等。
- README 之間的自動同步檢查，以及在 README 中新增指向線上展示站的連結。
- 簡體中文用詞品質的自動化驗證，由維護者審閱清單確認。

## 補充說明

- 英文優先是整個功能的原則：套件簡介、主 README、預設縮圖與無對應語言時的導向目標全部以英文為準。
- 提交訊息依專案慣例使用繁體中文。
- 實作時請先切到功能分支，不要直接在 main 上作業。
- 套件管理與執行一律使用 bun。
- 實作時最容易靜默出錯的是語言清單：先收斂成單一來源，再擴充語言。
- 簡體字典的詞彙與詞彙表的簡體對照要互相一致，建議先補詞彙表的簡體對照，再翻譯字典與 README。
