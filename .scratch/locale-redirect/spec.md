# 依瀏覽器語言導向的三語展示站

## 問題陳述

展示站的根網址目前直接顯示英文頁面，繁體中文版藏在 `zh-TW/` 子目錄，唯一的入口是每頁標頭上的語言切換連結。讀繁體中文的訪客打開根網址，得先看到英文、再自己找切換連結；讀簡體中文的訪客則完全沒有對應版本，只能讀英文或繁體中文。切換連結也佔用標頭空間，並要求每頁額外維護一個跨語言連結。

## 解決方案

展示站提供英文、繁體中文、簡體中文三個對等的語言版本，各自放在 `en/`、`zh-TW/`、`zh-CN/` 目錄。訪客打開根網址 `/miniflow/` 時，根頁面依瀏覽器的偏好語言自動導向對應的語言目錄，沒有對應語言就導向英文。直接打開任一語言目錄下的網址則一律尊重網址，不再導向。所有頁面移除語言切換連結。

## 使用者故事

1. 身為使用繁體中文瀏覽器的訪客，我想要打開展示站根網址就直接看到繁體中文頁面，以便不必先讀英文再找切換選項。

3. 身為使用其他語言瀏覽器的訪客，我想要打開根網址看到英文頁面，以便在沒有對應翻譯時仍有可讀的預設。
4. 身為偏好語言清單排序為日文再繁體中文的訪客，我想要系統略過不支援的日文並選用繁體中文，以便偏好順序被正確尊重。
5. 身為偏好語言清單第一項為英文、第二項為繁體中文的訪客，我想要看到英文，以便第一偏好優先。
6. 身為使用香港或澳門繁體中文瀏覽器的訪客，我想要進入繁體中文頁面，以便讀到符合書寫習慣的版本。
7. 身為使用新加坡簡體中文瀏覽器的訪客，我想要進入簡體中文頁面，以便讀到符合書寫習慣的版本。

10. 身為瀏覽器語言代碼大小寫不一致的訪客，我想要仍被正確判斷，以便不因大小寫差異落到錯誤的語言。

12. 身為想刻意閱讀其他語言版本的訪客，我想要直接修改網址的語言目錄就能切換，以便不依賴站上的按鈕。
13. 身為展示站訪客，我想要頁面標頭沒有語言切換連結，以便標頭更簡潔。
14. 身為按下上一頁的訪客，我想要回到導向之前的網頁而不是被卡在導向頁，以便瀏覽紀錄不被污染。
15. 身為關閉 JavaScript 的訪客，我想要在根網址看到三個語言的連結並自行選擇，以便仍然進得去展示站。
16. 身為搜尋引擎，我想要在根頁面與每個內容頁都看到各語言版本的替代連結，並知道預設版本是英文，以便正確關聯三個語言版本。

26. 身為讀簡體中文的開發者，我想要簡體 README 的術語與詞彙表的簡體對照一致，以便照著文件寫出的規格與文件對得上。

28. 身為使用 AI agent 協作的維護者，我想要同步約定寫明是三份 README，以便 agent 修改其中一份時會同步另外兩份。
29. 身為維護者，我想要支援的語言清單只有一個來源，以便新增語言時不會因為漏改某個陣列而被靜默略過。
30. 身為維護者，我想要新增一個語言時只需補一份文字字典，且缺任何字串時型別檢查就報錯，以便翻譯漏洞在提交前被發現。
31. 身為維護者，我想要語言偵測的所有對照規則有自動化測試保護，以便調整規則時不會悄悄壞掉。

34. 身為維護者，我想要縮圖只有一張，以便範例改版時只需重做一次。

## 實作決策

**輸出結構與語言**

- 支援三個語言：英文、繁體中文、簡體中文。內部語言代碼分別是 `en`、`zh-Hant`、`zh-Hans`；輸出目錄名稱分別是 `en/`、`zh-TW/`、`zh-CN/`。語言代碼與目錄名稱各自獨立設定。
- 英文頁面從輸出根目錄搬進 `en/`。根目錄只剩導向頁，不再放任何內容頁。三個語言目錄的頁面集合完全對稱：總覽頁、三張獨立流程頁、三份 SVG，以及 Web Component 互動頁。
- 支援語言的清單只有一個來源，其他需要列舉語言的地方一律從它推導，包含展示站建置器的迴圈與測試。不得再出現手動維護的語言陣列或二元判斷。
- 三份範例規格工廠與展示站外殼字典都新增簡體中文。簡體字典手寫完整內容，與英文、繁體中文並列維護，不從繁體自動轉換。字典鍵集合必須完全一致，缺漏由型別檢查擋下。
- 簡體用詞採中國大陸慣用詞，不沿用台灣用語。詞彙表未涵蓋的簡體詞，由實作者翻譯，並在交付時列出清單供維護者確認。

**導向頁與語言偵測**

- 根目錄的 `index.html` 是導向頁，頁面本身就是極簡的語言選單：列出 English、繁體中文、简体中文三個連結，每個連結的名稱用該語言自己的文字。同時在 `<head>` 放各語言版本的 `hreflang` 替代連結，預設版本標為 `x-default` 並指向英文。導向頁的 `lang` 為 `en`，社群預覽使用共用縮圖。
- 偵測在瀏覽器端執行，不依賴伺服器重導，也不依賴 Hub 的任何設定。偵測成功後用取代目前紀錄的方式導向，使用者按上一頁不會停在導向頁。
- 偵測規則依瀏覽器偏好語言清單的順序，取第一個有對應的語言：
  - `zh-TW`、`zh-HK`、`zh-MO`，以及帶 `Hant` 字形標示的代碼，導向繁體中文。
  - `zh-CN`、`zh-SG`，帶 `Hans` 字形標示的代碼，以及單純的 `zh`，導向簡體中文。
  - 字形標示優先於地區，例如帶 `Hant` 與 `CN` 的代碼導向繁體中文。
  - `en` 與 `en-*` 導向英文。
  - 其他語言視為沒有對應，略過並看下一項。清單為空或全部沒有對應時，導向英文。
  - 比對時不區分大小寫。
- 導向目標由目前的網址路徑計算：以導向頁所在目錄為基準，少了結尾斜線時自行補上，再接上語言目錄。不寫死任何部署前綴。
- 偵測邏輯寫成純函式，輸入偏好語言清單，輸出三個語言之一；它的原始碼在建置時內嵌進導向頁，使導向頁沒有執行期依賴。
- 只有根路徑做偵測。直接進入任一語言目錄下的網址一律尊重網址，不導向、不儲存任何偏好、不記憶選擇。

**內容頁**

- 移除所有頁面標頭的語言切換連結，連同只為它存在的語言名稱欄位與判斷邏輯一併清除。
- 每個內容頁的 `<head>` 放三個語言版本同一頁的 `hreflang` 替代連結。這是不可見的語言關聯，取代切換連結原本的角色。
- 站內導覽連結與互動頁的範例切換按鈕仍留在目前語言目錄內，頁面之間沒有任何跨語言連結。
- 每頁依語言設定 `<html lang>`、`<title>`、描述與社群預覽標籤。簡體中文頁面的 `lang` 為 `zh-Hans`。

**縮圖**

- 所有語言的頁面共用同一張英文標籤的縮圖。不再有繁體縮圖，也不新增簡體縮圖。各語言目錄下的頁面以相對路徑指向輸出根目錄的共用縮圖，導向頁直接指向同一張。
- 建置腳本的縮圖複製只剩一個檔案。README 中關於重新產生縮圖的說明改為只描述一張縮圖。

**文件**

- 新增簡體中文 README，章節結構與程式碼區塊數量與另外兩份對應，範例使用簡體標籤。三份 README 頂端的語言列互相連結，術語以詞彙表為準。
- 專案的 AGENTS.md 中 README 同步約定由兩份改為三份。
- 詞彙表的每個術語新增一行簡體對照，全部都列，即使與繁體字形相同。詞彙表本身仍是繁體中文。
- 既有的雙語展示站規格仍描述著「兩個語言、英文在根目錄、每頁有切換連結、不做自動偵測」。依專案的文件維護原則，直接改寫成現行決策，不堆疊修訂註記；已完成的歷史票券不回頭改。

**部署**

- 部署流程不變：整個輸出目錄原樣同步到 Hub，且同步前會先清空 Hub 上該應用的目錄，所以舊的根目錄英文頁面會在下一次部署時自然消失。這是刻意的取捨，不留相容用的導向頁。

## 測試決策

**好測試的標準**：只驗證對外可觀察的輸出，不驗證字典內部結構、模板字串拼接方式，也不比對整份 HTML 的快照。

**測試接縫**：沿用既有的兩個接縫，不新增。

- 展示站建置器：不接受外部輸入，回傳「相對路徑到檔案內容」的對照表。
- 三份範例規格工廠。

語言偵測不新增獨立接縫。測試從展示站建置器的輸出取出導向頁，在假的偏好語言清單與假的網址位置下執行其內嵌腳本，驗證導向結果。如此測的是實際會部署的程式碼，也一併涵蓋補結尾斜線與取代目前紀錄的行為。

**要驗證的行為**

- 輸出對照表的根目錄只有導向頁；`en/`、`zh-TW/`、`zh-CN/` 三個目錄各自含完整的頁面集合，且檔案清單兩兩對稱。
- 各語言頁面的 `lang` 屬性正確，簡體為 `zh-Hans`。
- 導向頁含三個語言的連結與 `hreflang` 替代連結，預設版本指向英文。
- 每個內容頁含三個語言同一頁的替代連結，且畫面上的站內連結都不跨語言。
- 所有頁面的社群預覽圖都指向共用縮圖，相對路徑隨目錄深度正確。
- 導向行為，逐項對應上方偵測規則：
  - 各地區與字形代碼的對照。
  - 偏好順序與略過不支援語言。
  - 單純中文導向簡體。
  - 字形標示優先於地區。
  - 大小寫不敏感。
  - 清單為空導向英文。
  - 網址缺結尾斜線時仍導向正確位置。
  - 導向時取代目前紀錄。
- 每個語言的每份範例規格都能通過 `render` 的輸入驗證而不拋錯；三個語言的節點 id、格位與連線集合完全一致。
- 英文頁面與英文 SVG 不含中文字元。簡體頁面保留簡體內容，並與繁體頁面的對應文字不同。
- 沒有任何手動維護的語言陣列：測試本身從單一來源推導語言清單。

**先例**：既有測試都是針對純函式輸入輸出的斷言，以字串包含與結構比對為主。新測試沿用同樣風格；既有的導向與切換連結相關斷言，會被「沒有切換連結、沒有跨語言連結」取代。

## 不在範圍內

- 依瀏覽器語言導向以外的語言偵測，例如依地理位置或 Cookie。
- 記住使用者的語言選擇，包含 localStorage。
- 為舊的根目錄英文網址保留相容的導向頁。
- 修改 Hub 倉庫的設定，或依賴伺服器端重導。
- 為任一語言產生獨立縮圖，以及縮圖的自動化產生流程。
- 詞彙表、ADR 與其他 agent 文件的英文化或簡體化，詞彙表只加簡體對照行。
- 英文、繁體中文、簡體中文以外的其他語言。
- 函式庫本身的任何行為變更。
- README 之間的自動同步檢查，以及在 README 中新增指向線上展示站的連結。
- 簡體中文用詞品質的自動化驗證，由維護者審閱清單確認。

## 補充說明

- 提交訊息依專案慣例使用繁體中文。
- 目前在 main 上，實作前請先切到功能分支。
- 套件管理與執行一律使用 bun。
- 實作時最容易靜默出錯的是語言清單：舊程式碼有手動維護的語言陣列、二元的另一語言判斷，以及測試中寫死兩個語言的陣列，漏改時型別檢查不會報錯。先把語言清單收斂成單一來源，再擴充第三個語言。
- 簡體字典的詞彙與詞彙表的簡體對照要互相一致，建議先補詞彙表的簡體對照，再翻譯字典與 README。
- 建議的實作順序：語言清單單一來源與簡體字典、展示站建置器的目錄結構與導向頁（含測試）、移除切換連結與加入替代連結、縮圖精簡、詞彙表與 README 與 AGENTS.md、最後改寫既有的雙語展示站規格。
